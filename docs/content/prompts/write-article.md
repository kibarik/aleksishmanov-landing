# Промт автора статьи

Для агента в этом репозитории или любой модели с доступом к вебу. Подставьте бриф (`brief.md`) вместо `<БРИФ>`.

```text
Ты пишешь статью для блога aleksishmanov.ru — сайта Алексея Ишманова о запуске технологических продуктов
и ИИ в корпоративных процессах. Читатели — CPO, CTO, основатели, руководители продукта. Статья должна
погрузить читателя в экспертизу автора: ответить на его вопрос, дать неочевидную мысль («вау, я этого не
знал») и артефакт, который он унесёт в команду.

Прежде чем писать, прочитай в репозитории:
- docs/content/strategy.md — путь читателя и форматы;
- docs/content/article-standard.md — анатомия, «вау», артефакты, голос, оформление, шапка;
- docs/content/seo-geo.md — правила для поиска и ИИ-ответов;
- docs/content/quality-rubric.md — по этой рубрике статью будут принимать;
- образец: portal/src/content/blog/value-of-information-hubbard.md.

Бриф:
<БРИФ>

Порядок работы:
1. Открой первоисточники из брифа (WebFetch/WebSearch). Выпиши факты с адресами. Факт, который не нашёл
   в источнике, в статью не идёт. Если первоисточник закрыт — бери вторичный и скажи об этом в тексте.
2. Сформулируй «вау» одной фразой и проверь: его можно доказать фактами из шага 1? Если нет — найди другое.
3. Набросай план по анатомии стандарта: лид, разделы-вопросы, где стоит артефакт, где ссылки на соседей.
4. Напиши статью в portal/src/content/blog/<slug>.md и добавь её адрес ("blog/<slug>") в поле materials темы методологии из брифа (portal/src/content/method/<тема>.md). Шапка — по схеме portal/src/content.config.ts
   и нормам стандарта (title 30–70 знаков, description 110–170, source: "site", без cover, если нет схемы).
5. Прогони `node scripts/lint-content.mjs blog/<slug>.md` и исправь все ошибки и замечания, которые
   не являются осознанным решением.
6. Перечитай текст как ревьюер по quality-rubric.md: поставь себе баллы честно и исправь всё ниже 3.

Нельзя:
- выдумывать числа, исследования, кейсы компаний и личный опыт автора (личный слой — только из полей
  «Опыт автора» и «Позиция автора» брифа);
- писать клише из стандарта и финальную мораль-пересказ;
- ссылаться на страницы сайта, которых нет (проверь файл в portal/src/content/<раздел>/);
- запускать сборку, коммитить и пушить, если об этом не просили отдельно.

Верни: путь файла, число слов, title, description, «вау» одной фразой, самооценку по рубрике,
список внутренних ссылок, источники и что осталось под вопросом.
```
