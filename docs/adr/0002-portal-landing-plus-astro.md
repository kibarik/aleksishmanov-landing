# Портал: 3D-лендинг на Vite + страницы на Astro, одна статическая сборка

aleksishmanov.ru становится единственным сайтом: на нём собраны блог Teletype, три Telegram-канала, промты и презентации.
Главная остаётся 3D-лендингом (vanilla JS + three.js, Vite, `index.html` и `src/`). Все остальные страницы строит Astro
из Markdown в `portal/src/content/`. `scripts/build.mjs` собирает обе части и сливает их в один `dist/`. Если обе части
создают один и тот же путь, сборка падает. Серверной части нет, как и в ADR 0001: формы и чата нет, «Написать» ведёт в Telegram.

Заменяет ADR 0001 в части «SPA»: сайт многостраничный, у каждой страницы полный текст в HTML.

## Почему Astro

Критерии владельца: код целиком пишут ИИ-агенты, сервер не нужен, SEO и продвижение через ИИ. Сравнивали четыре генератора:

| | Astro 5 | Next.js (static export) | Eleventy 3 | Hugo |
|---|---|---|---|---|
| Контент в Markdown со схемой | коллекции + zod: ошибка сборки, если агент пропустил поле | вручную | вручную | front matter без схемы |
| 3D-сцена лендинга | Vite внутри, тот же стек | нужно оборачивать в React | Vite отдельно | отдельный пайплайн |
| JS на странице статьи | 0 по умолчанию | рантайм React | 0 | 0 |
| sitemap, RSS | официальные интеграции | вручную | плагины | встроено |
| Насколько хорошо знают ИИ-агенты | очень хорошо, документация в llms.txt | очень хорошо | средне | средне (Go-шаблоны) |
| Лицензия, живость | MIT, активный | MIT, активный | MIT, активный | Apache-2.0, активный |

Выбран Astro. Next.js (как у prompts.aleksishmanov.ru) отклонён: на каждой странице был бы рантайм React, а сцену
пришлось бы переписать. Eleventy и Hugo слабее по схеме контента и по знанию ИИ-агентами.
Версия 5.x: Astro 7 требует Node ≥ 22, а локальная среда и сборка Timeweb пока на Node 20.

## Почему лендинг не переносится в Astro

Предложение владельца — разделить стек: у лендинга свои тесты (золотые кадры, производительность, фолбэк без WebGL),
и над ним параллельно работают другие сессии. Перенос в Astro поменял бы чанки и тайминги без пользы для поиска.
Текст для поиска на главную добавляет Vite-плагин `scripts/vite-portal.mjs`: при сборке он рендерит секции в HTML
тем же `renderSections`, что и браузер.

## Consequences

- Две команды разработки: `npm run dev` (лендинг, :5173) и `npm run dev:portal` (портал, :4321). Сборка — `npm run build`.
- Шапка и подвал у портала свои (`portal/src/components`), у лендинга — свои (`src/sections.js`). Общие только тексты:
  имя, позиционирование, профили.
- Тесты: E2E лендинга не изменились. Портал проверяется против собранного `dist/` (`npm run test:portal`),
  правила импорта и редиректа — юнит-тестами (`npm run test:unit`).
