# Контент — Markdown в репозитории, импорт один раз, дальше правки в файлах

Каждый материал — файл `portal/src/content/<раздел>/<slug>.md` со схемой из `portal/src/content.config.ts`.
CMS нет (решение владельца): материалы пишет и правит ИИ-агент, история правок — git.

Первоначальное наполнение — `npm run import` (`tools/import-sources.mjs`) из снимка источников, который скачал
`tools/fetch_sources.py`. Правила импорта:
- пустые и служебные посты, а также посты из одного заголовка со ссылкой отсеиваются;
- анонс статьи блога в Telegram сливается с самой статьёй: ссылка на пост попадает в `also_in`;
- одинаковые посты в разных каналах склеиваются. Нужны общая ссылка и похожий текст или заголовок.
  Подборка, где эта ссылка — одна из многих, дублем не считается;
- раздел: @ai_ossresearch → «Инструменты», пост со ссылкой на репозиторий → «Разборы», остальное → «Блог»;
- направление: по каналу и ключевым словам, одно или оба;
- адреса сайта — в нижнем регистре. Старые адреса сохраняются в `old_urls`, из них строятся страницы-переадресации.

Повторный импорт перезаписывает только файлы с `imported: true`. Доработанный вручную материал защищён:
при доработке флаг снимают. Отчёт последнего импорта — `portal/import-report.md`.

## Consequences

- Новый материал: файл в нужном разделе, поля по схеме. Сборка падает, если поля не хватает.
- Картинки — `portal/public/media/<раздел>/<slug>/`, презентации — готовые HTML в `portal/public/slides/<id>/`.
- Импорт больше не нужен, когда все материалы доработаны. Скрипт остаётся для новых выгрузок (Threads и т.п.).
