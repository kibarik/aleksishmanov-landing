# 08: Футер с 3D-элементом

**What to build:** внизу страницы знакомый видит тёмный футер с колонками ссылок, призывом «Написать» и собственным 3D-объектом — отдельный экран, а не строчка со ссылками.

**Blocked by:** 07 (Тёмная секция самопрезентации)

**Status:** done

- [x] Футер на всю высоту экрана, тёмный, с колонками ссылок из модуля контента
- [x] 3D-элемент рендерится во втором канвасе, стартует только когда футер попал в зону видимости, и останавливается когда ушёл
- [x] Без WebGL и на мобильном пресете вместо 3D показывается статичный кадр
- [x] Призыв «Написать» и копирайт на месте, ссылки ведут туда же, что и раньше
- [x] E2E: футер в потоке, ссылки совпадают с контентом, на no-webgl канваса нет

## Comments

- Реализовано: футер стал отдельным тёмным экраном во всю высоту — колонки «Проекты» и «Ресурсы» слева, призыв с кнопкой и якоря разделов справа, копирайт внизу. Всё из модуля контента (`content.footer.columns`, `contact`, `menu.anchors`).
- 3D-объект: `src/footer3d.js` — своя маленькая сцена во втором канвасе, хромированный глиф `{ }` с зеркальным металлом и окружением RoomEnvironment, медленное вращение плюс отклик на мышь. Модуль подгружается динамически и стартует/останавливается по IntersectionObserver, так что вне футера кадры не рисуются.
- Без WebGL и на мобильном пресете вместо канваса показывается статичный кадр (`footer__fallback`).
- Отступление: объект пока собран из имеющегося — генерация в hyper3d не отвечает (две попытки, обе оборвались по таймауту без ответа сервиса). Замена на сгенерированную модель — одна строка `MODEL_URL` в `src/footer3d.js`: материал, нормализация по высоте и вращение уже готовы.
- E2E `footer.desktop` (тёмный экран во всю высоту, светлая шапка, живой webgl-контекст, ссылка призыва) и `footer.no-webgl` (статичный кадр вместо канваса); проверка футера в `expectSectionsMatchContent` переписана под новую структуру.
