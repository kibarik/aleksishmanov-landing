# 07: Фолбэк без WebGL

**What to build:** знакомый без WebGL видит вместо чёрного экрана статичный кадр белой сцены (webp), обычную страницу со всеми секциями и светлую шапку; лоадер не появляется, бандл three не грузится. Кадр генерируется из самой сцены командой и лежит в репозитории.

**Blocked by:** 02 (Модуль контента), 04 (Секции после сцены)

**Status:** done

- [x] Инлайн-проверка в head: `getContext('webgl')` и `webgl2` с `failIfMajorPerformanceCaveat`; при провале атрибут на html, бандл сцены не импортируется
- [x] Первый экран показывает webp белой сцены (два размера: десктоп и мобильный, srcset), страница скроллится нативно, шапка в светлой теме, кнопка Ask видна
- [x] Скрипт генерации кадра: поднимает страницу, доводит до белой сцены, захватывает кадр через `__app.capture()`, сохраняет webp; README описывает команду
- [x] Кадр обновлён после финальных текстов имени и теглайна
- [x] E2E: проект no-WebGL видит картинку, не видит canvas и лоадер, секции присутствуют

## Comments

- Реализовано: инлайн-проверка `webgl2`/`webgl` с `failIfMajorPerformanceCaveat` в `<head>` ставит `html[data-webgl="off"]`. `src/main.js` стал точкой входа без three: общий контент и секции монтируются всегда, а сцена уехала в `src/boot3d.js` и подключается динамическим импортом только при живом WebGL. В фолбэке меню получает заглушку липкого скролла (`released: true`).
- Кадры: `public/fallback/white-desktop.webp` (39 КБ) и `white-mobile.webp` (18 КБ), в разметке `<picture>` с `media` по 1024px. Генерация — `npm run capture:fallback` (`scripts/capture-fallback.mjs`): поднимает dev-сервер, доводит сцену до белой сцены на обоих пресетах и снимает кадр через новый `window.__captureWebp(width, quality)`.
- E2E `tests/e2e/fallback.no-webgl.spec.js`: атрибут проставлен, лоадер и канвас скрыты, картинка видна, запросов к `character.glb` и Draco нет, шапка тёмная на светлом, кнопка Ask видна, страница скроллится и секции совпадают с контентом.
