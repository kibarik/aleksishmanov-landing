# Лендинг v1: путь посетителя от лоадера до проектов

## Problem Statement

Знакомые по работе (участники практикумов, коллеги по созвонам) хотят узнать, какие проекты и практикумы ведёт Алекс и как с ним взаимодействовать вне рабочих созвонов. Сейчас aleksishmanov.ru — статичный SPA с двумя карточками, без «wow», а новый лендинг с 3D-персонажем показывает только первый экран и заглушку из трёх блоков: путь посетителя обрывается на белой сцене, CTA ведут в никуда, тексты и язык смешанные, на устройствах без WebGL чёрный экран.

## Solution

Лендинг проводит знакомого по одному пути без развилок: лоадер с оффером → тёмная сцена → переход → белая сцена с именем и теглайном по направлениям → кнопка Ask Ishmanov AI → уход сцены → «Обо мне» → три карточки проектов → «Написать» → футер с ресурсами. Всё на русском, бренд латиницей. Каждое действие ведёт в Telegram (t.me/kibarik). Без WebGL показывается фолбэк-кадр белой сцены и обычный скролл. На телефонах облегчённый пресет. Новая страница заменяет главную aleksishmanov.ru; поддомены-ресурсы остаются.

## User Stories

1. As a знакомый, I want увидеть на лоадере фразу «Превращаю идеи в работающие бизнес-платформы», so that я с первой секунды понимаю, чем занимается Алекс.
2. As a знакомый, I want чтобы лоадер показывал реальный прогресс загрузки персонажа и заканчивался плавным включением света, so that ожидание не воспринимается как зависание.
3. As a знакомый, I want увидеть тёмную сцену с персонажем со спины, so that получить тот же «wow», что и у референса.
4. As a знакомый на десктопе, I want чтобы два-три тика колеса запускали переход с глитчем и пролётом камеры, а один тик откатывался назад, so that переход ощущается как осознанный жест, а не случайность.
5. As a знакомый на телефоне, I want чтобы свайп запускал переход с облётом камеры без глитча, so that переход читается на маленьком экране и не грузит устройство.
6. As a знакомый, I want увидеть на белой сцене имя «ALEKS ISHMANOV» (на телефоне «ALEKS») за спиной статуи, so that понимать, чей это сайт.
7. As a знакомый, I want увидеть теглайн «Руководителям. Специалистам. Фаундерам.» над именем, so that сразу понять, к какому направлению отношусь.
8. As a знакомый, I want увидеть статую на пьедестале с тенями и глифами кода вокруг, so that белая сцена выглядела так же детально, как у референса.
9. As a знакомый, I want увидеть под пьедесталом кнопку «Ask Ishmanov AI», so that задать вопрос, не листая дальше.
10. As a знакомый, I want чтобы кнопка «Ask Ishmanov AI» открывала личку Алекса в Telegram, so that получить ответ от человека, пока бота нет.
11. As a знакомый, I want чтобы «Ask Ishmanov AI» была и в навигации сверху, so that добраться до неё с любого места страницы.
12. As a знакомый, I want чтобы после белой сцены страница отдавала обычный скролл и сцена уезжала вверх, а персонаж задерживался в кадре чуть дольше контента, so that переход к контенту был плавным и не ломал привычный скролл.
13. As a знакомый, I want вернуться к тёмной сцене, докрутив страницу до верха и крутнув ещё раз вверх, so that посмотреть анимацию повторно.
14. As a знакомый, I want увидеть секцию «Обо мне» с фразой оффера и таймлайном «2016 разрабатываю backend, 2018 запускаю B2B-платформы, 2022 руковожу backend-командами, 2024 изучаю ML и LLM», so that оценить опыт Алекса без фото и логотипов.
15. As a знакомый, I want увидеть три карточки проектов в порядке PO-нейробаза, PMF-стратегии, Промты, so that найти проект по своему направлению.
16. As a знакомый, I want чтобы карточка содержала надпись направления сверху, название, одну фразу сути, три темы и все ссылки на ресурсы, so that понять проект без перехода на другой сайт.
17. As a знакомый, I want чтобы ссылки карточек вели на Telegram-каналы, каталог презентаций, библиотеку промптов и Threads, so that продолжить погружение в выбранный проект.
18. As a знакомый, I want не видеть ссылку на блог, пока он отдаёт ошибку, so that не упираться в сломанную страницу.
19. As a знакомый, I want увидеть блок «Написать» с кнопкой в личку Telegram, so that связаться с Алексом одним нажатием.
20. As a знакомый, I want увидеть в футере ссылки на все ресурсы (Telegram-каналы, Threads, Промты, Презентации), so that найти нужный ресурс без возврата к карточкам.
21. As a знакомый, I want открыть меню из навигации и перейти по якорям «Обо мне», «Проекты», «Написать», so that не крутить страницу вручную.
22. As a знакомый, I want чтобы меню внизу содержало ссылки на ресурсы, so that меню работало как «Мои ресурсы» на старом сайте.
23. As a знакомый, I want чтобы навигация меняла цвет с белого на тёмный при свапе в белую сцену, so that имя и меню оставались читаемыми.
24. As a знакомый, I want чтобы весь текст был на русском, а имя и надписи бренда латиницей, so that читать сайт без переключения языка.
25. As a знакомый без WebGL, I want увидеть статичный кадр белой сцены и обычную страницу, so that прочитать контент, а не смотреть на чёрный экран.
26. As a знакомый на слабом телефоне, I want чтобы сцена загружалась облегчённой (меньше треугольников, ниже DPR, без AO и глитча), so that страница не тормозила и не грела устройство.
27. As a знакомый на десктопе, I want чтобы сцена держала не меньше 50 fps во время перехода, so that анимация не дёргалась.
28. As a знакомый, I want чтобы страница грузила модель и шрифты с приоритетом, а аналитику после первой отрисовки сцены, so that первый экран появлялся быстро.
29. As a знакомый, I want чтобы страница вела себя одинаково в Chrome, Safari и Firefox на десктопе и в мобильном Safari, so that «wow» не зависел от браузера.
30. As a Алекс, I want чтобы Яндекс.Метрика считала цели «дошёл до белой сцены», «нажал Ask», «нажал Написать», so that видеть, доходят ли знакомые до действия.
31. As a Алекс, I want чтобы ссылка Ask заменялась на бота изменением одной константы, so that подключить бота без правок сцены.
32. As a Алекс, I want чтобы тексты карточек и «Обо мне» лежали в одном месте, отдельно от сцены, so that править контент без риска сломать 3D.
33. As a Алекс, I want чтобы фолбэк-кадр генерировался из той же сцены командой, so that не рисовать иллюстрацию отдельно.
34. As a Алекс, I want чтобы `vite build` давал статику для хостинга SPA без бэкенда, so that задеплоить на тот же хостинг, что и старый сайт.
35. As a Алекс, I want чтобы страница держала мета-теги, title и Open Graph на русском, so that ссылка в Telegram разворачивалась с правильным превью.
36. As a Алекс, I want чтобы прогоны Playwright проверяли путь посетителя на десктопе и телефоне, so that регрессии перехода ловились до релиза.

## Implementation Decisions

- **Путь посетителя и шаги.** Десктоп: init → тёмная сцена → into-white → белая сцена → уход сцены. Мобильный: init → тёмная сцена → белая сцена → уход сцены. Дальнейших 3D-фаз нет. Липкий скролл, commit 0.3, паузы 500 мс и константы ввода остаются как реализовано по референсу.
- **Ask Ishmanov AI.** Кнопка на белой сцене под пьедесталом и в навигации; появляется вместе с теглайном (десктоп с 75% сегмента into-white → full, мобильный с 88%). Ссылка берётся из одной константы контента, сейчас t.me/kibarik.
- **Уход сцены.** Как сейчас: после белой сцены сцена отдаёт нативный скролл, контейнер сцены становится частью потока и уезжает. Добавляется задержка персонажа: контейнер персонажа получает параллакс с коэффициентом меньше единицы относительно скролла на первом экране высоты, потом догоняет. Возврат в липкий режим при прокрутке вверх на самом верху остаётся.
- **Контент.** Все тексты (оффер, таймлайн, карточки, ссылки, теглайн, имя, ресурсы футера) описываются в одном модуле контента и рендерятся в разметку. Сцена читает оттуда только имя и теглайн. Тексты берутся с aleksishmanov.ru дословно; ссылка на блог исключена до починки.
- **Карточка проекта.** Направление сверху, название, фраза сути, три темы, список ссылок с внешним переходом. Три проекта: PO-нейробаза (руководителям: t.me/corporate_ai, slides.aleksishmanov.ru), PMF-стратегии (фаундерам: t.me/ai_pmf, Threads), Промты (специалистам: prompts.aleksishmanov.ru).
- **Обо мне.** Фраза оффера крупно и таймлайн из четырёх строк. Без фото и логотипов.
- **Навигация и меню.** Шапка: имя слева, кнопка Ask и кнопка меню справа. Меню — оффканвас с якорями по секциям и ссылками на ресурсы. Цвет шапки переключается классом темы при свапе.
- **Лоадер.** Фраза оффера вместо цитаты. Прогресс от загрузки модели, минимум 1.8 с, потом включение света и prelude.
- **Пресеты.** Выбираются по ширине 1024 при загрузке и не меняются при ресайзе. Мобильный: облегчённая модель (децимация до 100–200k треугольников с запечённой normal map, отдельный файл), DPR 1–1.5, без GTAO и глитча, тени 128. Десктоп: текущая модель, DPR до 1.5, GTAO только в тёмной сцене, тени 256 с прогревом и обновлением по событию, не каждый кадр.
- **Фолбэк без WebGL.** Инлайн-проверка WebGL в head до загрузки бандла три-js; при провале: скрытие лоадера, показ webp-кадра белой сцены как фона первого экрана, обычный скролл, шапка в светлой теме. Кадр генерируется командой из самой сцены (capture белой сцены в full) и лежит в репозитории.
- **Загрузка.** Бандл three в отдельном чанке, preload модели и шрифтов, critical CSS лоадера инлайн, Метрика подключается после события первой отрисовки сцены. Шрифты: Montserrat для имени и теглайна, Manrope для текста; заголовок в сцене рисуется после загрузки шрифта.
- **Аналитика.** Яндекс.Метрика с тремя целями, отправляемыми из событий таймлайна и кликов по кнопкам.
- **Мета.** Title, description, Open Graph и превью-картинка (тот же фолбэк-кадр) на русском.
- **Хостинг.** Статический билд без серверной части (ADR-0001). Пути ассетов относительные, чтобы билд работал на любом статическом хостинге.
- **Персонаж.** Текущая модель без рига; доработка через hyper3d вне этой спеки.

## Testing Decisions

- Один шов: Playwright E2E на собранной странице. Тест — это то, что видит и делает посетитель: крутит колесо или свайпает, читает текст, нажимает ссылку. Внутренние хуки `window.__sticky` и `window.__app` допустимы только для чтения прогресса и захвата кадра, не для управления.
- Хороший тест проверяет внешнее поведение: после N тиков прогресс достиг шага; после свапа тело в светлой теме и тагline виден; после ухода сцены страница скроллится и секция «Обо мне» в зоне видимости; ссылки карточек ведут на ожидаемые адреса; без WebGL показан фолбэк-кадр и нет канваса. Не проверяем позиции камеры, интенсивности света, уровни материалов.
- Визуальная регрессия: золотые скриншоты ключевых состояний (тёмная сцена, пик глитча, белая сцена, уход сцены) на десктопе 1440×900 и мобильном 390×844, сравнение через существующий `__compare()` с порогом по score, а не попиксельно.
- Прогон в двух пресетах: десктоп и мобильный (эмуляция touch). Отдельный прогон с отключённым WebGL через флаг запуска браузера.
- Прior art: ручные Playwright-скрипты этой сессии (прогоны с wheel-бёрстами и ожиданием prelude), `tests/log.md`, `src/compare.js`.
- Юнит-тестов логики скролла не делаем.

## Out of Scope

- 3D-фазы после белой сцены (взрыв глифов, интерактив с пропсами, аналог шахмат).
- Риг и анимации персонажа, доработка модели через hyper3d, портретное сходство.
- Telegram-бот Ask Ishmanov AI как продукт: только ссылка.
- Встроенный чат, формы, email, любой бэкенд.
- Видео-секция и портфолио заказных работ.
- Переключатель языка, английская версия.
- Починка blog.aleksishmanov.ru.
- Деплой и настройка хостинга (отдельный шаг, провайдер не назван).

## Сверка user stories (23.09.2026, после тикетов 01–11)

Выполнены истории 1–28 и 30–36. Реализация по тикетам: лоадер и тексты — 02, Ask — 03, секции — 04,
меню и тема шапки — 05, уход сцены и возврат — 06, фолбэк — 07, мобильный пресет — 08,
производительность и загрузка — 09, Метрика и мета — 10, кадры и сборка — 11.

Не выполнено полностью:

- **История 29 (Chrome, Safari, Firefox, мобильный Safari).** Chromium и Firefox проходят путь
  посетителя, WebKit не запускается: сборка WebKit для macOS 14 старше, чем ждёт Playwright 1.63
  (`Unknown setting: PushAPIEnabled`). Проекты `webkit` и `firefox` оставлены в конфиге; прогон
  в WebKit и мобильном Safari нужно сделать на другой машине или после обновления Playwright.
- **Решение «децимация с запечённой normal map» (Implementation Decisions, Пресеты).** Normal map
  не запечена: в исходной модели нет UV-развёртки (только POSITION и NORMAL), запекать не на что.
  Облегчённая модель — 150k треугольников с вершинными нормалями, 710 КБ.
- **История 28 (приоритеты загрузки).** Preload модели, инлайн critical CSS и `font-display: swap`
  сделаны; preload шрифтов — нет: файлы @fontsource получают хеши при сборке, статическая ссылка
  на них невозможна без выноса woff2 в `public/` и ручного `@font-face`.
- **История 27 (50+ fps).** Выполнена, но проверяется не в E2E: внутри общего прогона Playwright
  частота rAF упирается в vsync или загрузку CPU. Замер вынесен в `npm run perf` — на собранной
  сборке десктоп даёт 82 fps в переходе, мобильный 81.
